“Every response has the same three fields, so every client can be written once.”

A small surface, kept deliberately honest.

Inference is a model registry and inference API for the cases where a full serving stack is overkill. Create a model, run inputs through it and read the history back. Engines are pure functions, so identical requests always return identical results.

Engines

Three engines, each one a pure function.

Same input, same output, every time. Swap in a real backend later without changing a single response shape.

All 3 model types →

text-generation

config: maxChars

Returns generated text for any input, optionally truncated to maxChars.

input  Explain tokenization
output {"text": "Generated response for: Explain tokenization"}

text-classification

sentiment lexicon

A tiny lexicon classifier with negation handling. Labels are positive, negative or neutral.

input  I love this great product
output {"label": "positive", "score": 0.8808}

embedding

config: dimensions 1–1024

A unit-length vector from a stable hash of the input. Five dimensions by default, up to 1,024.

input  hello world
output {"embedding": [-0.362459, -0.145358,
           -0.054593, 0.304294, 0.867133]}

Capabilities

Register, infer and inspect, under one roof.

From a single call to a full audit trail, five capabilities share one contract.

All endpoints →

Create, list, fetch and delete models. Names are unique and trimmed, types are validated, and type-specific config is checked before anything is stored.

  • POST /models
  • GET /models
  • GET /models/{id}
  • DELETE /models/{id}
See the reference →

Send a string to a model and get a completed inference back with its output, timestamps and measured latency in milliseconds. Run up to 64 inputs in one batch, or stream a text-generation result token by token over Server-Sent Events.

  • POST /models/{id}/infer
  • POST /models/{id}/infer/batch
  • POST /models/{id}/infer/stream
Run one now →

Every model keeps its most recent inferences, oldest evicted first. List the whole history, page through it with limit and offset, or fetch a single inference by id. The full total comes back in X-Total-Count.

  • GET /models/{id}/inferences
  • GET /models/{id}/inferences/{inferenceId}
See the reference →

A health endpoint reports version, uptime, model and inference counts, and /metrics exposes Prometheus counters and latency histograms. Every response carries x-request-id and x-response-time-ms, and unhandled errors are logged, never leaked.

  • GET /health
  • GET /metrics
  • x-request-id
  • x-response-time-ms
Check health →

Set API_KEY and every route except health and the docs requires Authorization: Bearer or X-API-Key. Keys are compared in constant time, and failures return the usual envelope with a 401.

Design notes Since v0.1

Small enough to read in an afternoon. Strict enough to trust in production.

  1. Deterministic by design

    Engines are pure functions with no network, no randomness and no model weights. Tests assert exact outputs, and so can yours.

  2. Bounded by default

    At most 1,000 models, 1,000 inferences per model, 64 inputs per batch and 100,000 characters per input. Tune each with an environment variable, and bad values fail at startup.

  3. One envelope, everywhere

    Success, data and error on every response, including 404s, 405s and validation failures. Clients never parse two shapes.

How to run it

Four commands from clone to first inference.

Needs Python 3.12 and uv. The only runtime dependencies are FastAPI and Uvicorn.

  1. Step 1Install

    Sync dependencies

    Creates a virtual environment from the lockfile.

    uv sync --extra dev
  2. Step 2Port 3000

    Start the server

    Listens on 0.0.0.0:3000. Override with HOST and PORT.

    uv run python -m src.server
  3. Step 3201 Created

    Register a model

    Pick a type, give it a unique name.

    curl -X POST localhost:3000/models -H 'content-type: application/json' -d '{"name":"demo","type":"text-classification"}'
  4. Step 4Milliseconds

    Run an inference

    Use the id from the previous response.

    curl -X POST localhost:3000/models/$ID/infer -H 'content-type: application/json' -d '{"input":"I love this"}'
